# ADR-0088: Offline Inter proportional UI font and text measurement

Status: Accepted

## Decision

General UI text (Home, Settings, and other Atrium chrome built through
`logos-ui-graphics`) renders through a bundled, offline Inter coverage atlas
instead of the fixed 8x16 JetBrains Mono atlas. Two fixed pixel styles are
bundled: `InterStyle::Body` (14 px) and `InterStyle::Title` (20 px). Terminal
and the retained `TextGrid` node (ADR-0087) are unaffected and keep addressing
JetBrains Mono directly; nothing about their raster path changes.

Inter is offline and native to the no-allocator Display raster path, the same
posture ADR-0084 established for Material Symbols: no webfont, no dynamic
font loading, no shaping or kerning, ASCII only (0x20..=0x7e). Unsupported
scalars render one deterministic replacement glyph, matching ADR-0017's
existing JetBrains Mono fallback.

`third_party/Inter-Regular.ttf` is Inter v4.1
(<https://github.com/rsms/inter/releases/tag/v4.1>), SIL Open Font License
1.1; the licence text is bundled at `third_party/Inter-OFL.txt`, alongside the
existing JetBrains Mono and Iosevka OFL texts.

## Measurement API

Advance widths are the single source of truth shared by two ownership
domains that must never disagree:

- `logos-ui-graphics` (the UI scene builder) needs them to size and center
  labels *before* any frame is drawn.
- `logos-display` (the sole framebuffer writer, per ADR-0069) needs them to
  advance the raster cursor while actually drawing.

Rather than let each recompute or hand-tune its own numbers, the advance
tables live once in `logos-abi` (`abi/src/font.rs` + generated
`abi/src/inter_advances.rs`), which both crates already depend on. Raster
coverage bitmaps stay `logos-display`-only.

```rust
// logos_abi
pub enum InterStyle { Body, Title }
impl InterStyle {
    pub const fn cell(self) -> (usize, usize); // fixed raster cell (w, h) px
}
pub const fn inter_glyph_advance(style: InterStyle, scalar: u32) -> u8;
pub fn inter_text_width(style: InterStyle, text: &[u8]) -> u32;
```

`inter_text_width` is the sum of per-glyph advances with no kerning or
shaping; it is what `ui-graphics::text_width` calls to center labels
(`push_text`/`push_avatar_text`), replacing the old `len(text) * 8 * scale`
Mono-pitch estimate.

## Wire ABI

`GuiDrawCommand::glyph_run_styled`'s `auxiliary` field gains two new mutually
exclusive text flags, alongside the existing light/double-size flags:

- `GUI_TEXT_FLAG_FONT_INTER_BODY`
- `GUI_TEXT_FLAG_FONT_INTER_TITLE`

Neither flag set (the default, e.g. the FPS overlay and any other raw
`GlyphRun` caller) keeps today's JetBrains Mono behavior unchanged. Both bits
set is rejected by `GuiDrawCommand::is_valid`. `logos-ui-graphics` sets one of
the two on every `GlyphRun` it emits: `Text4xl`-styled nodes (existing
"large text" style token) get `InterStyle::Title`, everything else gets
`InterStyle::Body`. Text4xl no longer requests the double-size Mono scale for
UI text; Inter's own 20 px atlas replaces that scaling trick.

## Raster path

Display resolves the font from the command's flags (`TextFont::from_flags`)
and, for Inter, indexes directly into the committed atlas bytes per glyph —
no glyph cache is needed (unlike Mono's accented-Latin1 runtime overlays,
ASCII Inter glyphs carry no runtime-computed variants). The raster cursor
walks forward by each glyph's own advance instead of a fixed pitch, so
`base_command_rect` (used for damage and clipping) and the rotated/scaled
sampling path (`glyph_source_coverage`) both measure width the same way the
scene builder did.

## Fixed bounds and limits

- Atlas cells: body 16x18 px, title 22x25 px, both large enough that every
  measured advance width fits inside its own cell (asserted by a host test).
- `services/display/src/inter_body_16x18.bin` / `inter_title_22x25.bin`:
  96 ASCII glyphs (0x20..=0x7e) plus one replacement glyph, 8-bit coverage,
  row-major, generated by `scripts/gen_inter_atlas.py` — no manual editing.
  Sizes are asserted at compile time (`const _: () = assert!(...)`) against
  `logos_abi::INTER_GLYPH_COUNT`/`INTER_BODY_CELL`/`INTER_TITLE_CELL`.
- The rotated/transformed sampling path performs one bounded
  (`<= MAX_GUI_TEXT_BYTES` = 32) linear scan of the running advance sum per
  destination pixel to locate the source glyph; deliberately not cached, since
  it only pays for text under active rotation/scale, which UI labels rarely
  are.
- No kerning, shaping, ligatures, bidi, or dynamic loading. Non-ASCII scalars
  render the replacement glyph, exactly like Mono's existing fallback.

## Consequences

- Home, Settings, and other Atrium screens gain readable proportional body
  text and are no longer forced through mono-grid math for label placement.
- Screens that previously assumed 8 px per character must (and now do) go
  through the measurement API to avoid clipping or misplaced centering.
- Terminal and TextGrid keep their existing fixed-pitch guarantees untouched.
- Regenerating the atlas only touches two generated files
  (`services/display/src/inter_*.bin`, `abi/src/inter_advances.rs`); no
  hand-maintained glyph tables to keep in sync.
